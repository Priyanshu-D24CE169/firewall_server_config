## 2. Current `/etc/fstab` configuration

The relevant entries are:

``` fstab
# Swap
/dev/disk/by-uuid/b515ddd3-23e8-4dcf-a4de-e1592bd082d2 none swap sw 0 0

# Root filesystem
/dev/disk/by-uuid/335647cb-c0f3-493d-9613-bea30b556c55 / ext4 defaults 0 1

# Boot filesystem
/dev/disk/by-uuid/2289e6f5-1274-41f4-a7ea-7f4b440e35a3 /boot ext4 defaults 0 1

# Dedicated 16 GB temporary partition
UUID=eb0e7a26-287f-4656-ad27-1bfcad5259fe /tmp ext4 rw,noexec,nosuid,nodev,relatime 0 2

# RAM-backed /var/tmp, maximum 1 GB
tmpfs /var/tmp tmpfs rw,noexec,nosuid,nodev,relatime,size=1G,mode=1777 0 0
```

Keep the actual root, boot and swap entries generated by Ubuntu if they
differ. Do not add duplicate mount entries.

## 3. Temporary-directory security

Both `/tmp` and `/var/tmp` are configured with:

-   `noexec`: prevents direct execution of binaries from the mounted
    filesystem.
-   `nosuid`: ignores set-user-ID and set-group-ID bits on that
    filesystem.
-   `nodev`: prevents device files on that filesystem from being
    interpreted as device nodes.
-   `relatime`: updates access times with reduced write overhead.
-   Mode `1777`: allows users to create temporary files while the sticky
    bit prevents users from deleting or renaming other users' files in
    the shared directory.

### `/tmp`

-   Backing device: `/dev/sda4`
-   Filesystem: ext4
-   Capacity: approximately 16 GB
-   Persistent disk-backed filesystem
-   Mount restrictions: `noexec,nosuid,nodev`

### `/var/tmp`

-   Backing filesystem: `tmpfs` (RAM-backed)
-   Maximum configured size: 1 GB
-   Mount restrictions: `noexec,nosuid,nodev`
-   Contents are lost on reboot.

**Behaviour change:** Traditionally, `/var/tmp` is used for temporary
files that may survive a reboot. Using `tmpfs` means its contents do not
survive reboot. Confirm that this is acceptable for the services
installed on this server.

## 4. Verified mount status

The following commands were run successfully:

``` bash
findmnt -no TARGET,SOURCE,OPTIONS /tmp
findmnt -no TARGET,SOURCE,OPTIONS /var/tmp
```

Observed output:

``` text
/tmp     /dev/sda4 rw,nosuid,nodev,noexec,relatime
/var/tmp tmpfs     rw,nosuid,nodev,noexec,relatime,size=1048576k,inode64
```

Directory permissions were checked with:

``` bash
stat -c '%A %a %n' /tmp /var/tmp
```

Observed permissions:

``` text
drwxrwxrwt 1777 /tmp
drwxrwxrwt 1777 /var/tmp
```

A direct execution test from `/tmp` was attempted:

``` bash
sudo ./test.sh
```

It returned:

``` text
sudo: unable to execute ./test.sh: Permission denied
```

This confirms that direct execution from `/tmp` is blocked by the
`noexec` mount option.

## 5. Useful maintenance and verification commands

### View block devices and filesystem UUIDs

``` bash
lsblk -f
sudo blkid
```

### View the active mounts and options

``` bash
findmnt /tmp
findmnt /var/tmp
findmnt -no TARGET,SOURCE,FSTYPE,OPTIONS /tmp
findmnt -no TARGET,SOURCE,FSTYPE,OPTIONS /var/tmp
```

### Check directory permissions

``` bash
stat -c '%A %a %n' /tmp /var/tmp
```

Expected mode for both directories:

``` text
1777
```

### Validate `/etc/fstab`

``` bash
sudo findmnt --verify
```

If systemd reports that `/etc/fstab` has changed, reload its unit
configuration:

``` bash
sudo systemctl daemon-reload
```

### Apply mount changes

After validating `/etc/fstab`:

``` bash
sudo mount -o remount /tmp
sudo mount /var/tmp
```

If a mount command reports an error, inspect the exact error and current
mount state before retrying. Do not format the partition as a
troubleshooting step.

## 6. Important security limitations

`noexec` is a useful hardening measure, but it is not a complete
execution sandbox. An interpreter may still be able to read a script
from a `noexec` filesystem and execute its contents. Do not treat this
mount option as a substitute for application isolation, user
permissions, or firewall controls.

The current configuration intentionally leaves `/var` and `/` without
`noexec`. Applying `noexec` to all of `/var` can break software and
services that legitimately execute files stored beneath it.

## 7. Change-control precautions

-   Back up `/etc/fstab` before future edits:

    ``` bash
    sudo cp -a /etc/fstab /etc/fstab.backup
    ```

-   Do not format `/dev/sda4`; it is the existing `/tmp` partition.

-   Do not remove or change the UUIDs without checking `lsblk -f` and
    `blkid`.

-   Do not add duplicate `/tmp` or `/var/tmp` entries.

-   After editing `/etc/fstab`, run `sudo findmnt --verify` before
    applying changes.

-   Re-check the active mounts after reboot.
